# P518 original save-contract plan

Static original inventory only; no native boundary/save proof or format support is claimed here. Fresh MEGAFILE.HYP is489731bytes, SHA256235de8b0fbb86b6cc1a8337779d6c6f7804e8455bce0dc607ea00092f3f6ffbd, byteFNV838a2480. Parser consumes all bytes. Mode0, one layer,32sprites,4locals,3startup programs,111commands,11declared sounds/introduction302, no movie/mouse rectangle/external-picture command.

Important correction: opcode39 chooses an unset mask bit using RNG; opcode20 is the external-image command, and P518 has none. Three opcode39 calls occur: startup selection, count8 delayed selection and ordinary positive-setting delayed selection. No recurring poll exists.

Original local declarations(raw fields): [[1,0,20,0,0,20],[1,1,9,0,0,511],[1,2,9,1,1,9],[1,3,20,0,0,20]]. Initial values are[0,0,1,0], from field3. Settled UI setting0..15 is clamped by controls5/6. local1 is nine-bit reservation mask, local2 selected planet1..9, local3 correct-release count. Preserve declared metadata and undeclared retained values; widths are not automatically value maxima.

Startup programs0/1/2 respectively update the setting indicators, draw/reserve a random unreserved planet, and attach the selected planet to launcher9. Indicators7 and19..32 form a prefix for the selected setting, not a one-hot choice. Clones19..32 inherit only sprite7 frames; their own coordinates/visibility remain distinct. Launcher9 starts603,10 with serialized movement[10,0,2,1,0] and rect[10,270,640,0]. Planet sprites10..18 all run independent native frame stepping every50ms, including hidden/untouched/stopped planets. Their frame counts are[3,3,11,11,3,1,1,1,3].

Release button8 plays a sound, releases only when setting>0, and increments local3 immediately if setting+planet==10 or setting−planet==9. At count9 it queues success after6500ms and exit388 after a further2000ms; at count8 it queues random selection after5000ms then follow; otherwise positive setting queues random after500ms then follow. The unlock is200ms later. At count8, setting0 STILL performs delayed random/follow even without a release. A zero-setting press therefore is not universally inert.

ScriptsIdle is distinct from motion idleness. After the next random/follow continuation completes, a new held planet can coexist with several older released planets still moving. Wrong releases keep their reservation until arrival; only then does native animate clear that bit. Correct-release count is not a landed count or popcount(mask). With all9 bits set, opcode39 consumes a random draw but leaves selectedid unchanged; subsequent follow can reattach the just-released planet. A dedicated rapid-launch/exhausted-mask native audit is required before asserting stronger count/mask/visibility relations.

A future first contract may admit trusted ordinary scriptsIdle with no queued actions, click lock/pulse, foreground narration, pending/displayed external image, movie or entered hover. It must preserve all32 own sprite records and both planetMotion and planetPeriod, beyond the established27words. Full32×29words plus605runner words and a10word clock/count/previous/audio/comet header/checksum would total6184bytes including ASVM/version. No format is assigned by this static plan. Rebuild callbacks/programs from the exact original scene, not serialized code or addresses.

Private mode0/period−1 denotes untouched ordinary planets; mode1/period10 follows; mode2/period10 is released active and mode2/period−1 is stopped after arrival. These fields cannot be derived from the old27layout. moveData[0] stores the chosen category0..15, NOT the actual movement period. Follow computes its proposed point using the old delta before copying launcher delta for the next step; don't equate its renderY or delta with the current launcher around a bounce. Release sets dx−2/dy0 while preserving the actual period and movement epoch. Arrival tests the old rectangle center after bounce can reverse velocity.

Correct arrival plays directS10, stops movement and preserves visible/frame animation. Wrong arrival plays directS9 and hides the planet, while preserving mode2, period−1, its last coordinate, stored planet id, selected category, frame/delta/epoch history and continuing autoFrame. Frame clocks evolve even on hidden objects; don't reset them at restoration. Previously successful planets can retain older categories independent of the current UI setting. RNG/state605, mask, selected id/count, clock/count/audio and dormant variant/comet state all belong in the contract.
