# Versioned candidate behavior requirements

The new schema turns the original resource syntax into a reviewable set of candidate behavioral requirements and attaches exact historical native observations. A fresh independent byte pass rechecks 421 original files and all 10,316 command records before the join. Native scene, offset, opcode, delay, numeric operands and hashed text operands must match each original command.

A command can contribute multiple cells. These counts describe requirements to investigate, not distinct reachable game branches. Reachability and required route outcomes remain unclassified. Alternative markers remain unlinked; the generator does not invent a nested-if interpretation.

The accepted historical trace maps 7,424 command entrances and observes 1,688 predicate-result cells at 1,087 original condition positions, 601 of them with both results. Its original diagnostic executable identity is retained. These controlled observations establish entrances and predicate results; they do not establish completed actions, timely dispatch, successful route outcomes or current-engine behavior. There are 1,096 predicate-result cells without this particular historical observation.

The native-callback and generated-queue catalogue remains open. Failure/success/timed outcomes need explicit reachability and completion evidence. The full per-command requirement detail stays local; the exported receipt contains counts, per-scene summaries and input/detail hashes. A03 remains open, and whole-game completion is unmeasured. Fixed acceptance remains 7/10.

The generator requires the local accepted syntax inventory, historical trace map, native proof and native log. These research inputs are retained in the development workspace. The normal engine installer/build does not invoke this research helper. No original media, text bodies, physical save fixtures or native executable are exported.
